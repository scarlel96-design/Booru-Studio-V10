# Gate 6.5 — Sprint 7 Readiness Gate

Gate 6.5 is a contract/QA reinforcement checkpoint between the sealed Sprint 6 gallery slice and
Sprint 7 media implementation.  It adds no yt-dlp/FFmpeg/Browser implementation and does not change
Sprint 6's product behavior.  Its purpose is to remove ambiguous choices before managed media and
Windows productization expand the failure surface.

## Locked before Sprint 7

1. **Presentation semantics are domain state.** A single media source is `INDIVIDUAL`; playlist,
   channel, multi-input and gallery sources are explicit `BATCH` collections. QML must not infer this
   from row count or URL shape.
2. **Managed engine capability reporting is truthful.** Control is reported as EXACT,
   CONFIGURABLE, BEST_EFFORT, OPAQUE or UNSUPPORTED rather than pretending every external engine is
   governed like DirectHTTP.
3. **Managed network activity has an admission envelope.** CONFIGURABLE/EXACT paths receive an
   explicit granted parallelism. OPAQUE paths have no claimed granted parallelism and are admitted by
   conservative weight only.
4. **Retry multiplication is bounded.** V10 outer attempts x engine inner attempts must fit under a
   hard compound attempt ceiling.
5. **TransferDescriptor is runtime-only.** Signed URLs, raw headers, cookies, Authorization and
   credential-grant references remain ephemeral and have a dedicated secret-free diagnostic view.
6. **Updater success is transactional.** 100% download, staging, helper launch, parent exit and even
   candidate activation are not `SUCCESS`. Success requires a healthy installed candidate, identity
   verification, Core/DB/UI protocol/Worker/EnginePack/migration health and a committed current
   capsule pointer while the previous capsule remains recoverable.
7. **Windows gates are named now, not invented at RC.** QLocal same-user isolation, bootstrap
   freshness, Job Object orphan cleanup, frozen QML load, frozen Worker self-spawn and V9 updater
   regressions are release-blocking scenarios.

## Sprint 7 may now implement

- yt-dlp Resolver/ManagedMedia adapter in Worker ownership only;
- normalized single media / playlist / channel descriptors;
- `ManagedMediaExecutionPolicy` generated by Core/Scheduler and consumed by Worker;
- bounded internal yt-dlp retry settings derived from `RetryEnvelope`;
- truthful progress/pause/resume/capability reporting;
- direct handoff only when the resulting `TransferDescriptor` is not UNSAFE;
- minimum ffprobe/FFmpeg integration needed by controlled media, without moving advanced Browser
  work forward from Sprint 8.

## Sprint 7 must not do

- import yt-dlp in Core/UI/Domain/Persistence;
- make raw yt-dlp dictionaries a public Domain/IPC schema;
- persist format URLs, cookies, headers, player tokens or extractor private state;
- claim exact connection counts for managed engines unless measured/controlled exactly;
- use infinite or multiplicatively unbounded retries;
- wrap a single video in a synthetic Batch 1;
- make updater, installer, Browser fallback or native Supervisor part of Sprint 7 scope.
